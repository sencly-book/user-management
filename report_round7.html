1. 报告概述

1.1 本轮背景

系统新增了URL 抓取功能（/fetch-url），允许用户输入 URL 让服务器抓取内容。由于没有对 URL 做任何限制，攻击者可利用 file:// 读取服务器任意文件，或通过内网地址扫描和攻击内部服务。

1.2 什么是 SSRF？

SSRF（Server-Side Request Forgery）服务器端请求伪造。攻击者让服务器代替自己向内网或其他受限网络发起请求。可用来扫描内网端口、攻击内部服务、读取本地文件（结合 file:// 协议）。

VULN-23：SSRF 攻击内网服务🔴 严重

位置：/fetch-url — POST 路由

描述：未对 URL 的目标 IP 做任何限制，攻击者可让服务器访问内网地址（127.0.0.1、192.168.x.x、10.x.x.x），用于扫描内网端口或攻击内部服务。

攻击场景：url=http://127.0.0.1:5000/ → 访问本机 Flask 服务；url=http://192.168.78.130:3306 → 扫描内网 MySQL 端口。

VULN-24：file:// 协议读取任意文件🔴 严重

位置：/fetch-url — POST 路由

描述：未限制协议类型，攻击者可使用 file:// 协议读取服务器上的任意本地文件，包括源码、配置文件和系统敏感文件。

攻击场景：url=file:///etc/passwd → 读取系统用户列表；url=file:///etc/shadow → 读取密码哈希。

4. 修复方案

4.1 限制协议

parsed = urllib.parse.urlparse(target_url)
if parsed.scheme not in ("http", "https"):
  fetch_result = "不支持的协议，仅允许 http/https"

4.2 阻止内网地址

ip = socket.gethostbyname(hostname)  # 解析域名到 IP
ip_obj = ipaddress.ip_address(ip)
if ip_obj.is_private or ip_obj.is_loopback or ip_obj.is_link_local:
  fetch_result = "不允许访问内网地址"
