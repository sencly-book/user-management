VULN-01：密码明文存储 🔴 严重

位置：app.py — USERS 字典

描述：用户密码以明文形式直接硬编码在 Python 源代码中。一旦源代码被泄露（如 Git 泄露、服务器被入侵、代码审查），所有用户的密码将直接暴露。

攻击场景：攻击者通过任意方式获取到 app.py 文件内容 → 直接读取 "password": "admin123" → 无需任何破解即可获取管理员权限。

VULN-02：密码明文展示在前端 🔴 严重

位置：templates/index.html — 第 10 行

描述：登录成功后，用户密码原文通过 {{ user.password }} 渲染到 HTML 页面中。任何能看到屏幕、查看浏览器缓存、或通过 XSS 攻击的人都能获取密码。

攻击场景：用户登录后离开电脑 → 他人看到屏幕上的密码 → 获取账号完全控制权。

VULN-03：明文密码比对 🔴 严重

位置：app.py — login 路由

描述：登录验证时使用 USERS[username]["password"] == password 直接进行字符串比对。结合漏洞 VULN-01，数据库泄露后攻击者可立即使用获取的密码原文登录任意账号。

攻击场景：数据库泄露 → 拿到明文密码 → 直接登录系统。

VULN-04：HTML 注释泄露默认密码 🔴 严重

位置：templates/login.html — 第 1 行

描述：登录页 HTML 源码中包含以下注释：<!-- 调试信息 - 默认管理员账号 用户名: admin 密码: admin123 -->。虽然注释在浏览器中不可见，但任何人通过"查看网页源代码"(F12 / Ctrl+U) 即可获取管理员密码。

攻击场景：访问登录页 → 右键查看源代码 → 看到注释中的 admin/admin123 → 直接登录管理员账号。

VULN-05：页面明文提示默认账号 🟡 中危

位置：templates/login.html — 第 21 行

描述：登录页底部直接展示 <p class="login-hint">默认账号：admin / admin123</p>，所有访问登录页的用户都能看到管理员密码。降低了攻击者的信息收集成本。

VULN-06：Secret Key 过弱且硬编码 🔴 严重

位置：app.py — app.secret_key = "dev-key-2025"

描述：Flask 使用 secret_key 对 session cookie 进行签名。密钥 "dev-key-2025" 是固定的弱字符串且硬编码在代码中。攻击者知道密钥后可以伪造任意用户的 session cookie，无需密码即可登录任何账号。

VULN-07：无登录频率限制 🟡 中危

位置：app.py — login 路由

描述：登录接口无任何频率限制、无验证码、无失败计数。攻击者可以对所有用户进行无限次暴力破解或字典攻击，直至猜出密码。

VULN-08：Debug 模式开启 🟡 中危

位置：app.py — app.run(debug=True)

描述：以 debug=True 模式运行。当代码抛出异常时，Flask 会显示详细的 Python 调试页面，包含完整的调用栈、局部变量值和源代码片段，可能暴露密码、路径、环境变量等敏感信息。

4. 修复方案

VULN-01 & VULN-03：密码哈希存储与比对

使用 werkzeug.security（Flask 内置依赖）对密码进行 bcrypt 风格哈希处理。 generate_password_hash() 自动生成随机盐值并迭代哈希，check_password_hash() 在比对时从哈希值中提取盐值进行验证，整个过程不涉及明文密码。

from werkzeug.security import generate_password_hash, check_password_hash

# 存储时：自动加盐哈希
USERS["admin"] = {
  "password": generate_password_hash("admin123"),  # 每次生成不同哈希值
}

# 校验时：安全比对
check_password_hash(USERS[username]["password"], password)  # 返回 True/False

VULN-02：删除前端密码展示

从 templates/index.html 的用户信息列表中删除 {{ user.password }} 模板变量。 用户信息页面仅显示用户名、邮箱、手机号、角色、余额，不再包含任何密码相关字段。

VULN-04 & VULN-05：清除页面密码泄露

删除 templates/login.html 中的 HTML 调试注释和默认账号提示段落。 登录页面不再以任何形式泄露账号密码信息。

VULN-06：Secret Key 加固

优先从环境变量 SECRET_KEY 读取密钥；当环境变量未设置时，使用 os.urandom(24).hex() 生成 48 字符的随机十六进制密钥。攻击者无法预测密钥值，无法伪造 session。

# 修复后：环境变量 + 随机 fallback
app.secret_key = os.environ.get("SECRET_KEY", os.urandom(24).hex())

VULN-07：IP 级别登录限流

基于来源 IP 的登录失败计数器：同一 IP 连续 5 次登录失败后，临时封禁 5 分钟。 5 分钟后自动解封。使用内存字典记录失败次数和时间戳。

LOGIN_FAILURES = {}  # IP -> { count, first_failure }

def is_login_blocked(ip):
  if ip in LOGIN_FAILURES and LOGIN_FAILURES[ip]["count"] >= 5:
    if time.time() - LOGIN_FAILURES[ip]["first_failure"] < 300:
      return True  # 封禁中
    else:
      del LOGIN_FAILURES[ip]  # 5分钟后自动解封
  return False

VULN-08：Debug 模式环境变量控制

通过 FLASK_DEBUG 环境变量控制 debug 模式，默认关闭。 生产环境无需额外配置即可获得安全的运行模式。

debug_mode = os.environ.get("FLASK_DEBUG", "false").lower() == "true"
app.run(debug=debug_mode, host="0.0.0.0", port=5000)

7.2 安全建议

  • 数据库存储：生产环境应使用数据库（如 SQLite / MySQL / PostgreSQL）替代内存字典存储用户数据
  • HTTPS 加密：部署时使用 Nginx + Let's Encrypt 启用 HTTPS，防止中间人窃听
  • 密码强度策略：增加密码复杂度校验（长度 ≥ 8，包含大小写字母、数字、特殊字符）
  • 验证码：在登录页面集成 CAPTCHA（如 reCAPTCHA），进一步加强暴力破解防御
  • 日志审计：记录所有登录尝试（成功/失败）到日志文件，便于事后追溯
  • 定期更换密钥：SECRET_KEY 应定期轮换，并在部署时通过环境变量注入
  • 权限分离：遵循最小权限原则，普通用户和管理员应有不同的操作权限
