1. 报告概述

1.1 本轮背景

系统新增了XML 数据导入功能（/xml-import），该功能检测 XML 中的 <!ENTITY ... SYSTEM> 定义，提取文件路径并用 open() 读取本地文件内容后替换实体引用。这完全复现了经典的 XXE（XML External Entity）漏洞，攻击者可通过 file:///etc/passwd 读取任意服务器文件。

1.2 什么是 XXE？

XXE（XML External Entity）攻击者在 XML 中定义外部实体，指向服务器上的本地文件。当 XML 解析器处理实体引用时，文件内容被读取并返回给攻击者。这是 OWASP Top 10 常见漏洞之一。

VULN-27：XXE 读取任意文件🔴 严重

位置：/xml-import — POST 路由

漏洞代码：

// 手动检测 ENTITY + SYSTEM → 提取路径 → open() 读取 → 返回给用户
entity_match = re.search(r', xml_data)
file_path = entity_match.group(1)
file_content = open(file_path, "r").read()
// 将文件内容替换掉 &xxe; 后解析 XML
replaced_xml = re.sub(f'&{entity_name};', file_content, xml_data)

描述：代码检测到 <!ENTITY xxe SYSTEM "file:///etc/passwd"> 后，提取路径 /etc/passwd，直接 open() 读取文件内容，然后替换掉 &xxe; 引用，最终包含在解析结果中返回给用户。

VULN-28：敏感文件泄露🔴 严重

可利用的读取目标：

  • /etc/passwd — 系统用户列表 ✅ 已确认读取成功

4. 修复方案

4.1 移除 ENTITY/SYSTEM 检测逻辑

// 删掉检测 ENTITY/SYSTEM 并 open() 读取文件的代码
entity_match = re.search(r'
file_content = open(file_path).read() ← 删除

4.2 清洗 XML 后再解析

// 1. 移除 DOCTYPE 声明
cleaned_xml = re.sub(r']*>', '', xml_data)

// 2. 移除实体引用
cleaned_xml = re.sub(r'&\w+;', '', cleaned_xml)

// 3. 用 ElementTree 安全解析（默认不解析外部实体）
root = ET.fromstring(cleaned_xml)
